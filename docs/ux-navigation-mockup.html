Menu → Checkout Navigation

Should "Menu" be a 5th checkout tab? Analysis, wireframes, and recommended patterns for surfacing an escape hatch back to /menu from /cart and checkout.

The Question

Should "Menu" be a 5th (first) checkout tab?

The existing checkout flow has four steps in the progress bar. Adding Menu as a tab first seems intuitive — but is it the right pattern?

✗
No — Menu does not belong as a checkout tab
  • Tabs = progress, not navigation. Each checkout tab represents a completed stage of the purchase funnel (Cart confirmed → Details filled → Order reviewed → Paid). Adding "Menu" inverts this: tab 1 would be a destination you came from, not a commitment milestone you've passed.
  • It breaks the linear mental model. Users expect each tab click to mean "I completed this." A clickable Menu tab communicates "I can undo my cart decision" — which is confusing at the tab level but perfectly fine as an explicit escape button.
  • Commerce constraint. multistep_default maps tabs to checkout steps (PHP route + form state). An external /menu URL can't be a genuine step without a custom plugin — and abandoned-order cleanup logic would need to be added to handle navigation away during payment initialization.
  • 5 tabs is too many on mobile. The existing SCSS already collapses non-active tabs at <576px. Adding a 5th makes the desktop bar feel cramped and "Menu" would disappear on mobile right when users need it most.
✓
Yes — the underlying user need is totally valid, just needs a different pattern
The real gap: there is no prominent, always-visible path back to /menu once a user is in checkout. The back_to_cart_button module exists but provides a dismissible AJAX link inside the cart form — not prominent enough. Three targeted fixes solve this without polluting the progress bar:
  • A persistent "← Keep Ordering" escape hatch on the cart page — second CTA below Checkout
  • A breadcrumb escape hatch above the progress bar on all checkout steps (`/menu › Cart › …`)
  • A "Browse Menu Again" CTA on the completion page

Handoff Spec

Implementation specification

Four discrete issues, each independently shippable. Listed in recommended implementation order.

Issue What Where Approach
#11.1 "← Add More Items" button on cart page back_to_cart_button.module Change existing AJAX link to a normal <a> button with btn btn-secondary CSS. Remove AJAX dependency — simple navigation to /menu suffices. Promote weight to render above checkout button.
#11.2 Breadcrumb escape strip on all checkout steps Theme block or hook_preprocess_commerce_checkout_form Render a slim strip ← Menu › Cart › Checkout above the progress bar. Can be a custom block placed in a new checkout_nav region, or injected via #prefix in a hook_form_alter. Links: Menu → /menu, Cart → /cart. No JS needed.
#11.3 "Order More Food" CTA on /complete page store_fulfillment completion message OR theme template Override commerce-checkout-completion-message.html.twig in theme, or add a completion_cta pane (custom plugin) on step: complete. Renders "🍕 Order More Food" → /menu and "View Order History" → /user/orders.
#11.4 SCSS for escape strip (mobile-first) src/scss/components/_checkout-escape.scss New partial: slim strip, muted-yellow bg, auto-collapses "Changing your mind?" label at <576px, keeps icon + "← Menu" link visible at all breakpoints. Import in main.style.scss.
